# 子 agent 执行单元实施计划（SubagentRunner + spawn 双入口）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 `docs/superpowers/specs/2026-09-14-subagent-design.md` 落地子 agent 执行单元：SubagentRunner 单一权威（三形态解析 → fork 组装 → 执行 → 结论回写 → 工具面收窄），spawn 内置工具（主任务动态派生，同步 + 同轮批量并行）与 graph 角色节点（改薄入口）双形态同批交付。

**Architecture:** `src/harness/subagent.ts` 为子代理生命周期唯一权威——AgentRegistry（`agents/{id}/agent.md` 装配期一次性加载 fail-fast + ROLE_PRESETS 四角色内建注册，预设常量自 graph 迁入 harness 修正分层方向）；`runSubagent` 以 `seedHistory = [...chainView(), 角色行?, 任务行]` 起 fork 作用域 Reactor，私有步骤零主链回写、终态恰好回写一行结论/补丁行；子工具面 = 父 registry `derive`（缺省 − spawn，显式 `tools` 收窄/放开）；spawn 工具（category `subagent`）薄委托 Runner，同轮 `tools` 数组批量并行、同层 fork 并发上限 4；graph `makeRoleAgent` 改薄入口调 Runner。

**Tech Stack:** TypeScript strict（CommonJS）+ Node ≥ 22.9 + node:test；pnpm；零新增依赖。

## Global Constraints

- **前置依赖（硬）**：本计划 Task 3 起依赖 fork 实施计划（`docs/superpowers/plans/2026-09-14-context-fork.md`）Task 1（ContextManager 链 API：`chainView/appendChain`）与 Task 2（Reactor `scope:'fork'` + `seedHistory` + 收尾回写契约）先行合入；本计划 Task 1/2 无此依赖可先行。推荐全局执行顺序：fork 计划 Task 1→2 → 本计划 Task 1–6 → fork 计划 Task 3→5→6→7。
- **吸收关系**：本计划 Task 5 取代 fork 计划 Task 4 的 **role agent 半边**（makeRoleAgent 直接改薄入口调 Runner，不经过中间形态）；loop node fork 化仍归 fork 计划 Task 3/4，本计划不触碰 `src/loop/`。
- 前缀缓存第一要义（CLAUDE.md §11）：`spawn` 进工具清单按名排序、装配期冻结、运行期零增删（同 MCP 纪律）；主链↔fork 首帧严格前缀连续为强制回归项；fork 尾追只允许角色行/任务行出现在子首帧尾部。
- 定义加载装配期一次性 fail-fast（同 skills/MCP 纪律）；`agent_id` 未命中报「未找到智能体：`<id>`」不静默回退；所有失败显式返回码，禁静默降级。
- 文案规则：模型侧/链行文案 `pick()`、界面文案 `t()`，运行期求值，禁止模块级冻结（i18n 语言为启动参数）。

**Interfaces:**
- Produces:
  - `SubagentBudget { maxSteps: number; tokenCap: number; deadlineAt?: number; tier?: ModelTier }`
  - `SubagentRunner`（构造入参对齐 Reactor 可装配面：`{ safety, registry, context, model, onEvent?, ledger? }`）：
    - `attachParent(getBudget: () => SubagentBudget): void` / `detachParent(): void`——spawn 通道预算源（reactor run 起止挂/摘）
    - 并发计数 + `SUBAGENT_CONCURRENCY_LIMIT = 4`；超限返回 `Result.fail('CONCURRENCY_LIMIT', …)`
    - `runSubagent(input: SubagentSpawnInput, opts?: { taskLine?: string; label?: string }): Promise<Result<{ reply: string }>>` 统一入口：
      1. `resolveSpawnSpec` → roleLine/taskLine/label
      2. 并发护栏计数（try/finally 递减）
      3. 子 registry：`input.tools ? registry.derive({ only: input.tools }) : registry.derive({ exclude: ['spawn'] })`
      4. fork 组装：`base = context.chainView()`；`seedHistory = [...base, ...(roleLine ? [{ step, action, observation: roleLine }] : []), { step, action: 'task', observation: taskLine }]`（step 逐条按 nextChainStep 递进；action 取值与 HistoryStep 既有口径对齐）
      5. 子 Reactor（每次派生新建，同 graph 先例）：`scope:'fork'` + seedHistory + budget（maxSteps/tokenCap/deadlineAt/tier）；子 `onEvent` 包装转发父 onEvent，payload 附 `subagent: label`
      6. 终态回写（子代理返回制）：`r.done` → `appendChain([{ action: 'reply', observation: `[${label}] ${首行(r.reply, 截断300)}` }])`，返回 `ok({ reply: r.reply })`；失败/抛错 → `appendChain([{ action: 'deficit', observation: `[${label}] 失败：${原因}` }])`，返回 `fail`
