## 交付结论

- 交付向 Claude Code 形态对齐的五项记忆能力：会中自写记忆（经既有原子 write、Saved 回执）、记忆总开关（env + 会话内命令两层）、每次写入刷新 modified 时间戳、子代理自有记忆（agent.md 声明开启、独立目录）、容量两级（近满提醒 / 硬超限「写入成功但勒令精简」——两级不合并）。
- 关键取舍「索引派生化」：记忆索引由记录文件全量重建、拒绝直写 MEMORY.md——索引是生成物，允许手改必被覆盖、制造「改了却不见了」的歧义；同 slug 写入视为更新不产生副本。
- 常驻记忆条目恒在（含空集）：空集时模型才知道能写、写哪、怎么写；为此登记了一次性前缀断点。
- 子代理记忆注入 fork 私有尾块、主链零回写，保住「主链↔fork 首帧严格前缀连续」不变量；主记忆仍随冻结快照被 fork 继承；不做子代理记忆自动提取。
- SUNSHINE.md 与技能清单的会中变更以尾追承载：轮次起点读盘比对，SUNSHINE.md 不一致尾追最新磁盘全文（非 diff——规则文本需精确可执行；超 4KB 截断附 read 指针），技能清单尾追一行增量告知。
- 控制面不设 SUNSHINE.md 配置层（用户裁决）：SUNSHINE.md 与 CLAUDE.md 同定位——给模型的指令，不承载键值配置；本规格零新增工具、工具清单与稳定段零变化。
