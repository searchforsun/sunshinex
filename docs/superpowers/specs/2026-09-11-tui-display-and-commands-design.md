## 1. 背景与痛点（基于代码事实）

| # | 痛点 | 现状依据 |
|---|---|---|
| P1 | 长任务转写条数随步数线性膨胀：每段思考折叠一行 + 每工具两行，百步任务正文数百行，历史被顶掉 | `session.ts` `pushMsg`；思考逐段收束为 `✻ Thought for Ns` |
| P2 | 逐增量全量重绘：每个 reasoning / token / usage 片段都触发 state 拷贝 + notify，长思考期间重绘频率与内容量耦合 | `session.ts` `appendLive` 每增量 `notify()`；`usage` 分支每次 notify |
| P3 | 运行态观察面弱：现 Spinner 只有帧动画 + 英文动词 + 耗时/tokens，看不到「现在在干什么、最近发生了什么」 | `Spinner.tsx`（Pondering/Brewing… 帧动画）；无事件面板 |
| P4 | 运行中缺少独立于正文的状态摘要：思考尾巴在正文滚动但不承载「当前动作 / 耗时 / tokens」语义，用户无法一眼定位现状 | `Spinner.tsx`（仅帧动画）；正文尾部 6 行思考不承载动作语义 |
| P5 | 命令面薄：现 5 条（/help /new /compact /status /plan），缺 /todos /cost /model /queue 等高频项 | `SLASH_HELP`（session.ts:57） |

目标：长任务下正文保持时间线流式（答复 · 工具 · 思考折叠并存，折叠项在时间线占位、可展开），重绘频率与内容量解耦，补齐高频命令；细节（思考全文 / 事件）按需展开查看，不隐藏时间线占位。

## 2. 方案：会话层聚合 + 钉底实时区（已选定方案 A）

原则：`messages` 在**运行中**保持只增不改；「合并」发生在**轮收束时刻**——一次提交收束时把本轮 thinking 行归并为一条汇总行（可展开回看本轮 detail），运行中逐段单行保留进行感。**思考流式尾巴保留在正文**（对标 Claude Code 时间线体验，折叠 ≠ 移除）；钉底行作为不占正文的状态摘要并存；Ctrl+O 面板作为事件细节的补充视图。所有派生数据（实时行文案、面板内容、汇总行）由纯函数产出，session 控制器只做状态搬运。

## 3. 详细设计

### 3.1 轮末思考合并（解 P1）

- `ChatItem` 增加可选 `runSeq?: number`（`src/types.ts` 登记）：本轮内产生的 **thinking 行**打上本轮序号。轮的定义 = 一次提交的执行区间（`runTaskFlow` 开始到收束；`/plan` 流程的每个待办项各算一轮；串行队列保证轮不重叠）。
- 收束时刻（done / error / 未完成终止上屏之后）：将本轮全部 thinking 行归并为一条汇总行，**插在本轮首条 thinking 行的位置**；tool 行原位不动。空轮（无 thinking）不产生汇总行。

```text
运行中（逐段单行）              收束后（轮末合并）
✻ Thought for 8s               ⚙ exec npm test · ✓
⚙ exec npm test · ✓     →      ⚙ read session.ts · 42 行
✻ Thought for 15s              ✻ 本轮思考 12 段 · 3m12s
⚙ read session.ts · 42 行
✻ Thought for 9s
```

- 运行中单行维持现状文案 `✻ Thought for Ns`（减少回归面）；汇总行文案 `✻ 本轮思考 N 段 · <合计时长>`，**保留 `[Tab 展开]` 能力**：展开即回看本轮 detail（受 §3.2 预算约束）。合并的是「显示行数」，不删除信息。
- 未完成终止同样执行合并：先上屏「未完成终止」行，再合并，保持顺序可读。

### 3.2 detail 预算（防长任务内存与展开失真）

- **单轮 64KB**：轮末拼接超限时**保尾弃头**，头部以 `…(前 X KB 已省略)` 标注——近期思考对续跑更相关。
- **全局 512KB**：超限时按 runSeq 从最旧一轮开始释放 **detail 全文**；被释放的汇总行文案变为 `✻ 本轮思考 12 段 · 3m12s（详情已释放）`，展开时显示摘要占位（段数 / 时长，永不消失）+「详情已释放」提示。
- **时间线占位永存**：释放只作用于 detail 全文，汇总行（段数 / 时长摘要）始终保留在时间线里，长任务历史仍可回溯到「该轮有 N 段、耗时 M」粒度；detail 全文是否落盘 ledger 支持按需惰性回看，列为后续议题（见 §11），本轮不引入文件 IO。
- 两个常量集中定义、可调；`/new` 软重置时清零计数。

### 3.3 钉底实时行（解 P3 / P4，落地 §5.4 的实时区半边）

- 位置：**输入框下侧、状态栏上方**（与护栏 spec §5.4 定稿一致）；运行态常驻一行，空闲态隐藏。
- 文案：`✻ <动作> · <耗时>s · ↑<tokens>`。动作从最近事件派生：思考中 / `exec npm test`（toolCallLine 摘要）/ 等待审批 / 排队 N 项 / 生成答复；帧字符沿用现 Spinner 字符帧。tokens 取 metrics 本轮值。
- **升级**现 `Spinner`（挪位 + 升级：动作可读、中文化，英文动词轮换移除）并**保留**正文中的思考流式尾巴（`LiveArea` 的 thinking 分支维持现状 tail 6 行，不做删除；reply 实时流维持现状不动）。钉底行是思考流的**补充摘要**而非**取代**：两者并存，正文给「进行感 / 流式」，钉底行给「一眼可读的当前动作 / 耗时 / tokens」。
- 窄终端：从尾部截断加 `…`。

### 3.4 Ctrl+O 事件面板（解 P3）

- controller 维护**事件环形缓冲**（容量 200）：每条会话事件入缓冲记一行摘要（时刻 · 类型 · 单行摘要，如 `14:02:11 tool exec npm test → ✓`）。
- `Ctrl+O`：钉底行**原地展开**为多行面板（默认显示最近 10 行），再按收起；**运行中 / 空闲均可用**；面板内容不进正文。
- 定位为**补充视图**：不改动正文 tool 行 / 思考行 / reply 的流式呈现（它们仍在时间线原位），面板只是 200 条事件环形缓冲的集中检索入口。
- 键位已核实无冲突：`Ctrl+C` 退出、`Tab` 补全/展开、`⏎` 发送、`↑/↓` 历史、`\` 续行。

### 3.5 命令集扩展（解 P5）

新增 6 条（进 `SLASH_COMMANDS` 供 Tab 补全；`/help` 同步）：

| 命令 | 行为 |
|---|---|
| `/todos` | 正文列出当前计划待办（✓/· 与缩进）；无待办时提示 |
| `/cost` | 会话成本摘要：runs、累计 tokens、本轮 tokens、会话时长（全部取账本摘要与 metrics 既有字段，不新增埋点） |
| `/model` | 显示当前模型与供应商（复用状态栏既有装配信息）；切换提示用 `--model` 重启生效 |
| `/queue` | 列出排队中的提交；`/queue clear` 仅清队列、不打断当前任务 |
| `/expand` / `/collapse` | 全局展开开/关（与 `Tab` 等价的命令形态），并将展开切换放开到**运行中** |

既有 `/help /new /compact /status /plan` 保留。

### 3.6 重绘节流（解 P2）

- 高频事件（`token` / `reasoning` / `usage`）的 `notify()` 合并到 **~80ms** 批次（尾触发定时器，注入时钟可测）；收束类事件（tool-call / done / error / 审批）**立即放行**，关键状态零延迟。
- 长任务 notify 频率从「每片增量一次」降到「≤12.5 次/秒」，与内容量解耦。
- `MessageList` 行级 `React.memo`：合并后行数有界，未变更行不重渲。
- **不用** ink `<Static>`：append-only 无法回改历史行，与轮末合并、Tab 展开冲突。

## 6. 与护栏 spec §5.4 的关系

- 本设计实现 §5.4 的**钉底单行实时区 + Ctrl+O 面板**；「节点状态序列」（⏺✓◐ 流程条）依赖 B+ `/pipeline`，**不在本轮**——届时在同一钉底行上扩展，面板复用其承载，不再单开覆盖层。
- §5.4 的「键位调和」注记已同步修订为指向本设计的**事件面板**（v1 的「全文视图」概念随 v1 废弃，不再存在）。

## 7. 错误与边界

- 汇总行 detail 已释放时展开：显示摘要占位（段数 / 时长）+ `（详情已释放）`，无 detail 全文。
- `/queue clear` 运行中：仅清队列，不打断当前任务。
- 面板打开时进入审批：面板保持打开但不拦截审批框（审批优先，沿用现状层级）。
- 会话时长起点：首次提交时刻（metrics 既有）。

- `live-line.test.ts`：各动作来源文案、窄终端截断、空闲隐藏。

## 9. 阶段划分与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| A | 轮末合并 + detail 预算（含 runSeq） | 多段思考长任务收束后思考仅 1 行；单测全绿 |
