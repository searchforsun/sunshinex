## 交付结论

- 补齐两个对用户不可见的关键窗口：模型轮发起的「思考窗口」（此前只见 spinner 兜底动画）与工具「执行前窗口」（审批挂起期间调用行已上屏却无显式等待态）——模型轮发起/结束两事件 + 工具调用宣告即 pending、结果即 completed/failed，执行瞬间与完成态在事件面可区分。
- 关键裁决：三态建在事件面（harness 层），TUI/GUI 只消费同一状态面渲染、切换交互面零重推导；状态由事件流经纯函数推导（对标 CC 客户端形态），渲染层不做业务推断；审批挂起是 pending 的显式子态，与审批卡并存。
- 零破坏扩展：既有事件发射时机与文本载荷一字不动，只增可选字段；旁路遥测边界——新事件不进提示词、不进会话链，状态对象瞬态不落盘（恢复后 idle），前缀缓存零击穿。
- TUI 消费形态：spinner 从唯一兜底动画升级为消费状态相位（思考动词+耗时/活动调用行/等待审批标注；正文流式即输出态、静默不重复动画）；调用行宣告即上屏、结果到达原位转换；状态行复用既有槽位、帧高不变量保持。
- 服务端工具进度流不做（当前工具为同步单次调用、无进度信号源），登记为未来工具面增强。
