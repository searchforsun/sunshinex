## 交付结论

- 交付会话内核（方案 B 全量收敛）：事件流的转录投影/持久化/挂起/队列状态收敛为内核单点，TUI 与 GUI 退化为纯渲染视图（replay 历史 + subscribe 增量）——结束三端各自实现同构转录投影导致的渲染漂移（TUI 不丢、GUI 丢、daemon 重启转录清零）。
- 公开事件词汇收缩：内核只向视图层发段级事件，token 级流内遥测收为内核内部——增量拼接/配对/统计不再是视图层事务，三份重复投影失去产生土壤；条目携带完整元数据，GUI 渲染零推导。
- 用户裁定「不做旧档兼容」：旧会话档由新单档取代，开发期旧会话直接删除、daemon 忽略未知格式——零兼容层；run 执行生命周期不变（恢复的是历史显示，不是运行续跑）。
- 审批/提问挂起表下沉为内核会话状态：挂起是会话事件、不随连接生灭，多客户端重连不丢挂起卡。
- steer 等待队列内核化：持久化 + 变更事件实时广播（替代快照轮询），TUI 新增 Ctrl+Q 队列管理面板（查看/编辑/删除/插入/直接发送/重排），GUI 补编辑——双端队列管理面对齐。
- 边界裁定：表面行为零变化；TUI/GUI 只做渲染、数据同源，唯一差异 = TUI 单会话单窗口 / GUI 多会话多标签；future 登记不本轮做——GUI 单进程化（进程内直调内核、去前后端分离）与 run 执行器独立进程化。
