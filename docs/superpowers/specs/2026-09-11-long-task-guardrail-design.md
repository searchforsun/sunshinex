## 交付结论

- 交付长任务护栏下沉底座：超时/预算/步数停判收敛为底座单一判定（顺序超时→预算→步数），编排层节点边界与底座每步共用同一判定，根治三类病灶——入口绕过编排层（手写步数魔数）、护栏粒度错位（节点边界拦不住节点内部长循环）、装饰性终止参数（声明了但从不生效）。
- 交付主链接线与终止可见性：TUI 提交改走长任务模板（限额由模板终止参数换算注入），/plan 规划段并入同一条链；越限不抛错、返回未完成原因并强制上屏，成本账本照常落——修「静默停止无从判断完成、失败还是还在跑」。
- 关键取舍「不暴露引擎开关」：一条主链 + 任务形态驱动，引擎名不做成用户可见命令；/plan 保留为人类确认点；graph 走专有命令 `/pipeline <流程名>`（按「流程」而非引擎命名，缺省恒 Loop、不按任务形态自动升级），gate 审批复用既有审批面、节点开始/结束接入会话事件流。
- 预算双量纲取舍：上下文窗口压缩阈值与累计 token 硬上限是两个量纲，分离不合并——合并会让长任务在压缩阈值处被误杀。
- 运行态流程展示（阶段 C，与护栏主线解耦、可独立验收）：钉底单行进度条以状态序列承载节点活跃集合，不做带连线的 DAG（终端宽高约束下连线不可靠）；窄终端尾部截断、活跃节点优先保留。
