# UI 模式分层 Spec —— C 端简洁 × 开发者完整（Codex 风格保持）

> 2026-11-17 设计裁定文档。原则：**只做减法，不做加法**——不新增入口、不新增提示、不新增内容，只用「开发者模式」一个开关把既有工程能力分层收起，并把内部术语改写为用户语言。三栏壳、暗色 #181818、22px 圆角、token 体系全部保持；Sunx 是产品特色能力，默认原样在场，不进开发者模式也不加引导。

## 0. 总体思路

**只有一个开关：「开发者模式」**（设置 → 通用 → 界面模式，默认关）。关闭时界面即 Codex 式简洁：一个输入框、一份会话列表、一个任务板；打开时各区域按 §1 清单一次性恢复完整能力。所有分层只控制**显隐与措辞**，不改变任何业务逻辑与数据流。

```
设置 → 通用
  └─ 界面模式
       └─ 开发者模式   [开关]  （默认关）
            关闭 = C 端简洁界面；开启 = 完整工程能力
```

不设微调子开关、不搞档位矩阵：一个布尔贯穿全产品，用户心智成本最低，实现与测试面也最小。个别区域想要「状态驱动」而非「开关驱动」的（如顶栏改动统计 pill），按各节单独裁定，但都不是用户可调开关。

- 本 spec 对 Sunx 只做术语层的减法（§6：attach 等内部词不外露），不新增任何入口或提示。

## 2. 交互与状态规则

- 开关即时生效，无需保存按钮；设置覆盖层保持现行为（主题即改即见）。
- 单一持久化 key：`uiMode.developer`（on/off，缺省 off）。GUI 内以 `useUiMode()` 派生 `developer: boolean` 单源消费，禁止各组件自读设置。
- **状态驱动的降级不是删除**：开发者模式关闭时，隐藏区域的入口从界面上消失，但快捷键与命令面板仍可达（⌘K 搜「终端」能打开终端标签页）。理由：隐藏 ≠ 禁用，命令面板是逃生舱，避免「功能消失」的客服工单。
- 窄窗口行为不变（<856px 左栏浮层、右栏抽屉），与模式开关正交。

## 3. 左栏（ProjectMenu）——保持现状，不动

2026-11-17 用户裁定：左栏不参与本次分层。
- Recents 是默认工作区的固有内容，不可折叠；Archive 只有用户点归档按钮后才展示，本身已是「按需出现」。
- 现有分组（Projects/Recents/Sunx/Archive/Pinned）逻辑、右键菜单、搜索面板全部保持。
- 本 spec 对左栏唯一的保留项：术语表（§6）中的 attach 等内部词改写，纯展示层。

## 4. 主对话区

### 4.1 顶栏（ChatTopbar）减法
- 现状核对：改动统计 +N/−N 已是「有未审查改动才浮现」的状态驱动（`changesTotal !== null`），保持不动；动态计数按钮组已是「有计数才显示」，本次在普通态整体收起。
- 普通态：隐藏动态计数按钮组（ChatDynButtons）；保留菜单开合钮、工作区 split 按钮、会话标题、「…」会话操作菜单、改动统计、拖窗带。
- 开发者模式开：动态计数按钮组恢复显示。

### 4.2 工具回执保持现状
- 现状核对：工具段已有聚合折叠（「查阅了 N 次」类聚合头）、简洁模式段级折叠、办公模式不可展开——本次不改工具行渲染与文案。
- 后台任务回执格式（`<id> started in background — <名>`）保持最新裁定原样。

### 4.3 审批卡保持现状
- 不做改造。审批卡是全产品视觉最重的既有时刻，本次只做减法，不强化不新增文案结构（按钮动词「允许」「拒绝」若现行已是如此则不动）。

### 4.4 空态保持现状

- 2026-11-17 用户裁定：**只做减法，不做加法**——欢迎空态不新增示例任务卡片等内容，保持现状。空态引导类新增全部移入不做清单（§10）。

### 4.5 composer「+」面板两级化（2026-11-17 用户裁定：控制主动展示 vs 点击出现）

现状：面板常铺五个分区（图片、命令、技能、子智能体、智能体团队）全部主动展开，C 端一打开就面对全量实体列表。裁定：**C 端只主动露出必要入口，其余点击/输入才出现**。

- **主动入口（默认展开，开发者模式关）**：
  - 选择图片（置首区，现状保留）
  - 添加文件引用（`@`）——C 端最常用的上下文入口
- **次级分区（默认收起）**：命令 / 技能 / 子智能体 / 智能体团队四个分区收进一个「浏览命令与技能」disclosure（`<details>` 形态，与 Agent 卡内嵌展开同构），点击才展开、数据才加载（现有 lazy 加载逻辑不动）。不新增计数徽标等元素——收起本身即减法。
- **键盘通道不变**：`/`、`$`、`#`、`@` 直接触发对应列表，脚行快捷键提示保持钉底恒显——收起分区不等于断掉熟练用户的路径，与 §2「命令面板逃生舱」同一哲学。
- 开发者模式开：五分区全展开，恢复现状。
- 面板数据源（GET /commands、/settings/skills、agentsView/teamsView）与插入语义（`/cmd `、`/<id>`、`$<id>`、`#<id>`）一律不动，只动展开集合。

### 4.6 「打开标签页」快捷入口（2026-11-17 用户裁定终版）

现状两处入口形态不一：**欢迎页**四 pill（辅助对话/浏览器/终端/审查）、**会话内**两 pill（浏览器/终端）。快捷入口**不套「显示更多 | 收起」机制**（那是「+」菜单的约定，§5.1），改为按模式定死的固定集合：

| 模式 | 欢迎页 | 会话内 |
|---|---|---|
| 开发者模式开 | 终端、浏览器 | 审查、浏览器、终端、辅助对话 |
| 普通（C 端默认） | 浏览器 | 浏览器、辅助对话 |

- 普通=开发者模式的子集：普通态砍掉的是工程向入口（欢迎页去终端、会话内去审查与终端）。
- 现状对照：开发者模式两行即现状（欢迎页=终端|浏览器，会话内=审查|浏览器|终端|辅助对话），本裁定只新增普通行；实现时两处 pill 列表改为按 `useUiMode` 派生的常量。
- 终端、审查在普通态不上快捷入口，仍可从「+」菜单「显示更多」到达。

### 4.7 composer 右 pill：effort 滑条保留（2026-11-17 用户裁定）

- **effort 强度滑条两种模式都在场**——它是「这个回答要多深」的用户可感知选择，不是工程细节，属产品能力而非开发者配置。
- 现有措辞与档位文案（思考强度/极简~最大）保持不动。
- 上下文用量圆环仍只在开发者模式显示（纯工程指标）。

## 5. 右栏（TabStrip）

### 5.1 「+」新建标签菜单两级化（2026-11-17 用户裁定终版）

现状：菜单平铺 12 个入口（审查、产物、待办、计划、智能体团队、后台任务、记忆、学习技能、辅助对话、终端、浏览器、Sunx 看板）。裁定为四常驻 + 「显示更多 | 收起」，与快捷入口（§4.6，按模式定死的固定集合）互相独立：

- **常驻四项（默认显示，开发者模式关）**：
  - **待办、产物、浏览器、辅助对话**
- **末行「显示更多 | 收起」**：菜单底部一行切换钮（变暗，三级前景色），点「显示更多」展开其余八项（审查、计划、智能体团队、后台任务、记忆、学习技能、终端、Sunx 看板），点「收起」折回。展开状态组件挂载期记忆。
- **顺序不动（2026-11-17 用户裁定「这个顺序不要动啊」）**：拍平但保持既有 content→session→tools 菜单序，常驻四项即该序中的 产物、待办、辅助对话、浏览器；展开后其余八项按原序补在末行之前。
- **对话触发豁免**：由对话动作打开的标签（点 diff 摘要卡开审查、点子智能体转录开 Transcript）不受限制，照常出现在 TabStrip——菜单分级只管「用户主动新建」的入口。
- 欢迎页（无会话）沿用"只开能落地的"：普通态只露浏览器；开发者模式露浏览器+终端。
- 开发者模式开：12 项全平铺，不出现「显示更多 | 收起」行。

### 5.2 常驻标签

- 默认页签行为保持现状：不自动打开任何页签，零标签空态即「打开标签页」引导（§4.6）。
- 普通态：「+」菜单只露四常驻（§5.1）；对话触发打开的标签照常出现在 TabStrip。
- 开发者模式开：全平铺，溢出收纳菜单照旧。
- 窄窗口：行为不变（既有抽屉/浮窗，两种模式一致）；本次不新增图标条折叠。

## 6. 术语表

**2026-11-17 用户裁定：术语本次不改**——「审查」「思考强度/effort」保持现状，不改写。

唯一保留的术语相关动作（属既有行为，不新增文案）：
- SourceBadge（env/项目/全局）普通态不渲染（§7.3）。

## 7. 设置页（SettingsShell）——层级优化

### 7.1 通用页瘦身（2026-11-17 用户裁定：通用页已含不少开关，需控制密度）

现状通用页三组：界面与外观（主题/缩放/调色板/字体/语言/终端停靠，6 行）+ 路径（4 个目录行）+ 命令执行（shell）。裁定：

- **新增「开发者」组置顶**：唯一开关放这里，组头说明（「开启后显示终端、高级设置等面向开发者的能力」），不与现有开关混排（现有外观开关不变）。
- **「路径」与「命令执行」整组迁入高级**——目录路径和 shell 选择是开发者配置，C 端不需要在第一屏看到。迁移为独立 pane「路径与执行环境」，键值语义不动。
- **普通态外观行收口（2026-11-17 用户裁定「非开发者模式下办公模式/简洁模式/用量统计/终端都是关的……整体看一下」）**：
  普通态隐藏「界面模式 / 简洁模式 / 用量统计 / 终端」四行，取值由模式派生——办公模式恒开、简洁模式恒开、用量统计恒关、终端下栏恒关；存储值仅在开发者模式开启时生效（切回即恢复用户原选择）。
- **终端行位置（同日裁定「终端调到简洁模式下方」）**：terminalDock 行从字段序抽出，紧随简洁模式行。
- **开关语义一致（同日裁定「开关开=左侧内容开启，简洁模式和用量统计是反的」）**：简洁模式存储缺省由关改为**开**、用量统计由开改为**关**——与普通态强制值一致，开发者模式打开时开关显示不再与刚才的实际体验相反；其余布尔开关（暗色气泡/暗色代码/产物卡/开发者模式）经核对语义一致。
- **终端缺省关（同日裁定「终端缺省关，普通下不显示终端」）**：terminalDock 缺省由 on 改为 **off**（设置行未设置显示关；仅显式 on 才启用下栏），普通态本就由开发者模式门控不显示。
- 瘦身后通用页 = 开发者 + 界面与外观（普通态行数进一步收口）。

### 7.2 导航分组重组（不删任何 pane）

```
基础：通用、模型与提供方、快捷键
（以下四组仅开发者模式可见，按语义逐个分组）
上下文与记忆：上下文与限额、记忆、知识库与搜索、全局规范
执行与扩展：路径与执行环境（原通用页两组迁此）、技能、MCP、插件
智能体：智能体、智能体团队
系统：权限、高级
```
- 不再使用「通用/高级」两组同名的塌缩结构（组头与首项重名、高级组一口吞 12 项）。
- 提供方不做拆分（只做减法）：ProvidersPane 整体留在默认组，不新增「模型服务/源配置」两半。
- 开发者模式关：高级组整组不渲染（非折叠）；命令面板仍可跳转。

### 7.3 pane 内部不改

- 高级组整组在普通态不渲染（§7.2），因此 pane 内部无需再做行级折叠——两级层级由导航承接。
- 唯一改动：`SourceBadge`（env/项目/全局来源徽标）在普通态不渲染；开发者模式开时保持现状。（高级 pane 仅开发者可见，故此条实际只在开发者模式下生效于可见分布。）
- 复杂 pane（Agent/MCP/Providers 卡片列表）形态一律不动。

## 8. 视觉规范——不动

- 主题、色彩、字体、圆角体系、`sx-*` 命名、双主题 token 全部保持。**本次不做任何视觉改造**（圆角 token 重构、阴影 token 化、新动效一律不做，2026-11-17 用户裁定「只做减法」）。
- 唯一允许的可见变化来自「收起」本身：少显示一些入口、少显示一些分区。

## 9. 实施切片（建议顺序）

1. **切片 A（开关骨架）**：`developer-mode.ts` 偏好模块（LS + 根属性 + ui-pref-sync 双写）+ 通用页「开发者模式」组（一个开关）。
2. **切片 B（设置页层级）**：导航分层（高级组仅开发者模式渲染）+ 路径/命令执行迁独立 pane + SourceBadge 普通态隐藏。
3. **切片 C（composer「+」面板）**：命令/技能/子智能体/团队收进一个 disclosure，lazy 加载保持。
4. **切片 D（顶栏）**：普通态收起动态计数按钮组。
5. **切片 E（右栏「+」菜单四常驻 + 更多|收起）+ 空态快捷入口按模式定死 + 术语改写**。

每个切片独立可发布、可回滚；A+B 就能交付「C 端第一印象」的全部改善，C–E 逐步跟进。

## 10. 不做清单（防止 scope 膨胀）

- 不改三栏壳结构、不做界面档位矩阵（只有开关布尔）、不重设计 Sunx Board 内部。
- **不做任何加法**（2026-11-17 用户裁定）：不新增入口、不新增提示（含 Sunx 空态引导）、不新增示例内容（欢迎页示例任务等）、不新增徽标、不新增动效。
- **不改视觉**：不重构圆角 token、不做阴影 token 化、不引入新字体/配色/组件库。
- **左栏 ProjectMenu 不动**（2026-11-17 用户裁定）：Recents 是默认工作区固有内容，Archive 按归档按钮才出现，均已是合理形态。
- 不隐藏安全相关 UI（审批/权限/full-access 警示）。
- 不动 daemon 回执格式与「+」面板数据源/插入语义（GUI 展示层翻译即可）。
