# GUI 性能优化三期工程设计（历史链自动分段加载 + 缓存 TTL）

- 日期：2026-10-26
- 状态：设计待评审（brainstorming 产出；评审通过后经 writing-plans 出实施计划）
- 范围：src/serve/（snapshot 端点分页参数）+ gui/（attach 播种/prepend 归约/后台加载链/chatMem TTL）
- 前置关系：一期（P1 快赢 + 2026-10-26 二轮补强）与二期（分包 + keep-alive，2026-10-26-gui-performance-phase2-design.md）已交付。本三期 = 原规格 P3（历史链分页/载荷瘦身/缓存收敛）按用户裁定调整形态：**自动后台分段补全**（「先上车再补票」），非用户翻页触发。

## 1. 背景与用户裁定

现状：进入会话时 daemon 把 journal **全量**重放下发（网络载荷 → JSON 解析 → 内核 seed → 映射全链）；用户只看尾部 300 条，却为全部历史付加载成本——会话越长进会话越卡。

用户裁定（2026-10-26）：
1. 进会话**先加载最新几轮**（尾窗秒开）；
2. 进会话后**自动分段加载更老的历史，直到补全**——用户无感，不依赖向上翻页触发（「先上车再补票」，避免进入卡顿）；
3. 不活跃的会话**过一段时间自动剔除转录缓存**。

与原规格 P3 的差异：翻页触发从「用户滚顶/点按」改为「后台自动链」；「显示更早」按钮退化为加载未达时的兜底提示（见 §4.4）。

## 2. 目标与验收

| 指标 | 现状 | 目标 |
|------|------|------|
| 进会话首屏可用 | 全量下载+解析+seed（随历史线性变慢） | 仅尾窗（~300 条），体感恒定 |
| 快照载荷 | 全量（含 result.full 全量观测） | 尾窗页/翻页均 ≤ ~300 条且不带 full |
| 老历史补全 | 无（一次性全量） | 后台自动逐段，直至头部（完成态标记） |
| 会话缓存 | LRU-4 无时间界 | LRU-4 + 30min TTL（运行中不剔） |
| 兼容 | — | 无分页参数的老调用行为不变（契约测试钉住） |

全量门禁：`pnpm test`（daemon 契约）+ `pnpm --dir gui run test` + typecheck。

## 3. 红线

一/二期全部成果不回归：daemon 30ms 合批、映射缓存、组级 memo、帧隔离、content-visibility、keep-alive。**流式尾部不裂**是硬约束：prepend 老历史不得扰动 openRun/openSeg 游标与尾窗渲染。journal 落盘形态不动（全量观测随档是模型上下文恢复契约）。

## 4. 设计

### 4.1 daemon：snapshot 分页参数（传输面增量，向后兼容）

- `GET /session/:id/snapshot?tail=N`：返回最后 N 条 + `total` + `oldestSeq`（本次页内最旧条目 seq）；
- `GET /session/:id/snapshot?before=<seq>&limit=N`：返回 seq < before 的前 N 条（journal 条目 seq 单调且不可变——天然游标）+ `hasMore`；
- 缺省无参 = 现状全量（老客户端/TUI 逐字节不变，daemon.contract.test 增补）；
- **载荷瘦身随分页走**：分页响应的条目只带 `result.text`（既有 200 字符截断），剥 `result.full`——全量观测按需另拉（§4.5）。kernel 内存面仍持全量（daemon 内不受影响），裁剪只发生在快照出口。
- 前置核对（实施批内第一步）：TUI 恢复路径确认不经 GUI 快照出口（原规格 §5.2 已标注；若共用读取面则裁剪收窄到带 `gui=1` 类客户端声明）。

### 4.2 gui：attach 尾窗播种 + prepend 归约

- attach 只以尾窗 seed（`tail=300`，对齐渲染尾窗 RENDER_WINDOW）；快照响应带 `total/oldestSeq/hasMore` 入 ChatState 供加载链消费；
- reducer 增 `prependSeed(state, entries, meta)`：头部插入 + structureVersion 递增；不动尾部与 openRun/openSeg 游标（游标引用的是尾部 seq，头部插入无扰）；
- **mapCache 对位**：头部插入走全量重映射路径（页级频率可接受）；尾部流式帧仍走既有快速路径；
- 渲染尾窗 RENDER_WINDOW 语义保留：老数据到达后**不自动扩张可视窗**——滚顶时按既有「自动回放」机制扩窗（数据已在内存，扩窗零等待）；背景补全是「备货」，不是「上货架」。

### 4.3 后台自动加载链（先上车再补票）

- 触发：尾窗播种落定即启动；`while hasMore`：`before=oldestSeq&limit=300` 串行取页 → `prependSeed` → 下一页；
- **让路规则**（资源合理）：会话切走（非当前 openSessionId）即暂停链；切回续跑（从 oldestSeq 断点继续，已取页不重取）；会话运行中照常补老（与流式互不干扰——prepend 头部、流式追加尾部）；单页之间让出一帧（rAF/0 延时 await），不与流式渲染争主线程整段；
- **失败与重试**：单页失败指数退避重试（对齐 adapter 重试口径），三次仍败置「更早的会话暂时加载失败（点击重试）」顶栏内联提示行——用户可手动重试，也可等自动重试；
- **完成态**：`hasMore=false` 置 historyComplete，链终止；顶栏提示行退场；
- **指示器**：补全期间顶栏内联细条（「正在加载更早的会话…」），不用弹层不加交互负担；
- 竞态守卫：加载链会话代次绑定（切会话/重播种 gen 失配即弃在途页）。

### 4.4 「显示更早」按钮语义变化

- 数据未达区域（用户滚顶快于后台补全）：按钮显示「更早的历史正在加载…」（不可点，跟随补全进度自动消失）；
- 数据已达区域：现状行为（扩可视窗），文案不变；
- 滚顶自动回放既有机制保留。

### 4.5 全量观测按需拉取

- 工具行展开且 `result.full` 缺席时：`GET /session/:id/entry/:seq/observation` 单条拉取（daemon 从 kernel/journal 直取，内存命中零盘读）；加载态沿用现 diff 面骨架样式；失败回落 `result.text`。

### 4.6 chatMem TTL 剔除

- 现状 LRU-4（切会话/重挂读写即触碰）增时间维：桶记录 lastTouch；**30 分钟**未触碰的桶在触碰检查/周期清理（60s 定时）时剔除；
- 运行中会话（runningIds 含）不剔（活跃流不值得省这点内存，剔了反添重播种抖动）；
- 剔除后果 = 该会话重进时走 §4.1 尾窗快照（本来就是权威路径），配合三期尾窗秒开，剔除代价近零；
- 剔除有单测（TTL 到期剔、运行中豁免、触碰续期）。

## 6. 风险与对策

- **prepend 与流式竞态**：prepend 只动头部（seq < 尾窗最旧），流式只动尾部；两者作用于同一 entries 数组的不同端，chat-reducer 串行归约无并发写——竞态面在「加载链取页期间新事件到达」：页界按 seq 游标闭合，新事件 seq 恒大于已取页，无重叠。
- **内存上界**：补全完成后 gui 内存仍持全量条目（与现状一致，kernel CAP 2000 环形同界）——三期改变的是**加载时序与载荷**，不是稳态内存；TTL 剔除降低多会话驻留。
- **页风暴**：串行 + 页间让帧，无并发页请求；切走即暂停，后台不烧资源。
- **mapCache 全量重映射频率**：仅页级（每 300 条一次），非帧级——二轮缓存的快速路径在页间流式帧仍生效。

## 7. 业界口径对照

反向时间序分页 + 不可变游标（seq cursor）= 聊天/时间线类应用标准形态（Slack/Discord/Twitter timeline 同构）；「尾窗秒开 + 后台补全」= 先关键路径后填充（critical-path-first）；缓存 TTL = 常规内存卫生。与二期的 content-visibility/组级 memo 叠加：加载侧（本三期）与渲染侧（二期）正交。

## 8. 明确不做（本三期）

- journal 落盘形态改动（全量观测随档是恢复契约）；
- TUI 恢复路径改动（仅核对不共用，裁剪不出 GUI 出口）；
- 渲染侧全虚拟化（二期 content-visibility + 尾窗已覆盖）。
